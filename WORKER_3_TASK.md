### 2025-01-16: Await Expression Parsing in Parameter Defaults

**Issue:** Await expressions were being incorrectly parsed in parameter defaults of async functions.

**Root Cause:** Parameter defaults are evaluated in the parent scope, not in the async function body. The parser was not checking for parameter default context when parsing await expressions.

**Fix Applied:**
- Modified `unary_expression()` in `wasm/src/thin_parser.rs` (line 6809)
- Added check for `CONTEXT_FLAG_PARAMETER_DEFAULT` in addition to async context check
- Updated comments to explain the scope behavior

**Test Case:** Created `wasm/test-await-parameter-default.ts` to verify the fix

**Impact:** This ensures that `async (a = await 42) => {}` correctly emits TS1109 ("Expression expected") instead of incorrectly parsing await as an await expression.

**Commit:** `3d5de742f43` - "[Tier 1] Fix await expression parsing in parameter defaults"
