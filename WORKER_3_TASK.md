### What Was Fixed
The implementation adds support for `readonly T[]` (readonly arrays) and `readonly [T, U]` (readonly tuples) by properly handling `TYPE_OPERATOR` nodes in the type checker.

### Changes Made
1. **wasm/src/thin_checker.rs**: Added `get_type_from_type_operator()` method
   - Handles `readonly` modifier on array and tuple types
   - Wraps the inner type in `ReadonlyType` wrapper when the readonly operator is present
   - Also added handling for `TYPE_OPERATOR` in type literal context

### How It Works
- The parser already correctly parsed `readonly T[]` as a `TYPE_OPERATOR` with `readonly` keyword
- The solver's `lower.rs` already had logic to convert this to `TypeKey::ReadonlyType`
- The subtype checker already had logic to reject readonly-to-mutable assignments
- The missing piece was in `thin_checker.rs` which wasn't handling `TYPE_OPERATOR` nodes
- This commit adds that missing handler

- ✅ Mutable array/tuple can be assigned to readonly (covariant)
- ❌ Readonly array/tuple CANNOT be assigned to mutable (invariant)
